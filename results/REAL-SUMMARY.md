# Уровень 1 — настоящий код записи трёх сред (2026-10-07)

Агенты — процессы без LLM, но запись идёт **их собственным кодом**
(`real/`: OpenResearch — Rust, их `orx.db` в SQLite WAL; OpenScience — их
TypeScript-хранилище, JSON-файл на сессию плюс общий файл; OpenHuman —
их `sessions.db`, SQLite после отката на `journal_mode=TRUNCATE`).
Точка — 30 с, 3 повтора. ФС: `container` — внутри VM Docker Desktop,
`macos-bind` — папка мака, примонтированная в контейнер. Синтетика,
с которой сверяем, — `SUMMARY.md` (04–06.10). Матрица — `real/matrix.sh`,
сводная таблица ниже — `python3 real/summarize.py`.

## Выводы

1. **ФС контейнера: подтверждённое не теряется ни в одной среде до
   N = 200** (0 потерь, 0 битых баз за 66 прогонов). Ломается скорость.
2. **Один общий файл = очередь.** OpenResearch на контейнере: доля
   выполненных сохранений (медиана) 0,82 при N = 50, 0,43 при 100,
   0,27 при 150, 0,20 при 200; p99 — 0,4 / 1,3 / 2,1 / 2,9 с. Не теряет,
   но агент успевает сохранить пятую часть того, что хотел.
3. **Файл на сессию держит.** OpenScience на контейнере: 0,98 при
   N = 100, p99 52 мс (выше 100 не мерили). OpenHuman — до 150 без
   ошибок, на 200 p99 1,7 с и 34 ошибки записи.
4. **Папка мака + SQLite WAL = порча на их коде.** OpenResearch: база
   битая или нечитаемая в 20 прогонах из 24, при N = 2 — в 3 из 3.
   Из подтверждённых агенту сообщений потеряно 940 из 1387 (68 %).
   Первый прогон матрицы упал на этой порче (`real-openresearch-macos-bind-…-1314`,
   только сырые логи); проверка доработана — нечитаемая база = всё
   подтверждённое потеряно, перегнано (`…-1335`).
5. **Откат на TRUNCATE не спасает целиком.** OpenHuman на папке мака:
   битая база в 4 прогонах из 24 (уже при N = 2), падения агентов
   во всех N, потеряно 82 подтверждённых из ~71,8 тыс. — единичные,
   но не ноль. p99 4 с с N = 100.
6. **JSON-файлы на папке мака не портятся, а тормозят.** OpenScience:
   0 потерь, но общий файл при N = 50 принимает 47 % записей, при
   100 — 8 %; p99 личных записей 1,2 с.

Сверка с синтетикой: выводы 1, 2, 4 и 6 `SUMMARY.md` подтвердились на
их коде; вывод 2 (TRUNCATE убирает порчу) — **не подтвердился**: на коде
OpenHuman порча есть, хоть и реже.

«Потерь нет» здесь — потерь подтверждённого. Несделанные сохранения
(доля ниже 1) в потери не входят, хотя для пользователя это тоже
потерянная работа.
